## Viz strategy — decided 2026-06-11 (post-ladder, post-N-Queens incident, outside-voice reviewed)

Decision: **Tier 1 extension is the trust path; Tier 3 is the floor; Tier 2 goes dormant.**
Rationale: Tier 1's reliability comes from the dev loop (run/test/sweep/review), not from
who writes it — AI-assisted dev-time authoring (~1hr/pattern) collapses the economic case
for blind runtime generation. Tier 2 fully hardened (lint, cache governance, vm sandbox
replacement) converges to "Tier 1 with extra steps and weaker guarantees." Tier 3 (live
model-authored viz, enforcement-ladder-policed, measured ~100% action validity) covers
the unanticipated tail; recurring Tier 3 problems get promoted to Tier 1. Outside-voice
review (fresh-context subagent, 2026-06-11) concurred on rejecting inline author→critic
multi-agent; its Tier 2 P1s (output gate only gates caching not serving; ungated cache-hit
path; node:vm is not a security sandbox) become moot while Tier 2 is dormant but MUST be
fixed before any revival.

- [ ] **Make Tier 3 the off-registry default (disable inline Tier 2 generation)** — In `index.js:start_leetcode`, skip the Tier 2 pre-run (the `tier2Key` branch): off-registry problems go straight to Tier 3 (hasViz=false, live viz). Removes the 45s cold-generation wait and stops executing LLM-generated code against user-pasted input (the vm RCE exposure). Keep the machinery dormant (pattern_key plumbing, run_algorithm gate, authorAgent) — do NOT delete; revival criteria below. [REQUIRES: none — one-branch change]
- [ ] **Tier 1 extension batch 1 (dev-time authoring with Claude Code)** — Known-demand patterns: (1) parametric board-backtracking generator (table renderer, place/remove/conflict steps — covers N-Queens, Sudoku solver, knight's tour in one entry; outside-voice suggestion), (2) Container With Most Water LC11 + Trapping Rain Water LC42 (existing TODO above), (3) permutations backtracking variant (existing TODO above), (4) LC53/LC70 routing verification. Each entry: run() + mapper cases + pseudocode + capabilities + coverage/sweep tests + extraction-prompt routing. ~1hr each. [REQUIRES: none]
- [ ] **Demand-driven promotion loop** — Mine `viz_request` feedback, `fallback_reason` logs, and lc_sessions hasViz=false rows for recurring off-registry patterns; promote to Tier 1 in batches. This is the growth mechanism replacing Tier 2. [REQUIRES: batch 1 shipped + some traffic]
- [ ] **Tier 2 revival criteria (do not revive without these)** — Only if traffic shows a long tail Tier 1 batches can't keep up with AND Tier 3 step-tracking errors appear in viz-error reports. Prerequisites from outside-voice review: move `outputMatchesExpected` into the generation retry loop as rung zero (today it only gates caching — mismatched traces are SERVED); require `output` on result step (absent output passes the gate); lint on every execution incl. cache hits; replace `node:vm` (not a security boundary — isolated-vm or subprocess); background generation only (never inline). [REQUIRES: production evidence]
